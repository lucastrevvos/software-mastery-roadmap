# 00.7 — Profiling básico

## Modelo mental

`medir → localizar hotspot → formular hipótese → alterar → medir novamente`

## Conceitos

- baseline antes de otimizar;
- `real`, `user` e `sys`;
- profiler e hotspots;
- `ncalls`, `tottime` e `cumtime`;
- CPU-bound vs I/O-bound;
- crescimento de custo com a entrada;
- trade-off tempo × memória;
- benchmark precisa de comparação, não impressão subjetiva.

## Comandos

```bash
time python3 app.py
python3 -m cProfile app.py
python3 -m cProfile -s cumulative app.py
python3 -m cProfile -s calls calls.py
/usr/bin/time -v python3 app.py
top
```

## Mini-lab realizado

- comparação de busca de duplicados com loops aninhados e `set`;
- aumento da entrada para observar crescimento do custo;
- profiling com `cProfile`;
- contraste entre processo CPU-bound e espera com `sleep`;
- observação de CPU e memória.

## Armadilhas

- otimizar sem medir;
- confundir tempo de relógio com uso de CPU;
- concluir performance a partir de uma única execução;
- fazer micro-otimização quando o problema é algoritmo/estrutura;
- melhorar tempo ignorando o custo de memória.

## Levar desta aula

> Não pergunte primeiro “como deixar mais rápido?”. Pergunte “qual evidência mostra onde o custo está?”.
