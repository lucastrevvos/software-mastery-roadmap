01 · PRINCÍPIOS

O que este roadmap otimiza

Não há certificado como requisito de avanço. Evidência de capacidade é o gate.

01

Modelos antes de APIs

Entender o mecanismo o suficiente para prever comportamento antes de decorar a interface que o esconde.

02

Problemas antes de padrões

Primeiro reconhecer a estrutura do problema; só depois nomear algoritmo, pattern ou framework.

03

Debugging é currículo

Encontrar causa, formular hipótese, medir e corrigir é uma competência própria — não um acidente do projeto.

04

Ferramenta é veículo

Python, C, C#, JavaScript ou Rust servem ao objetivo cognitivo. A linguagem não define a fase da formação.

05

Produção faz parte

Software não termina quando compila: precisa ser testado, observado, implantado, degradado e recuperado.

06

Transferência vence repetição

Resolver 100 exercícios parecidos vale menos que resolver um problema novo sem receber a técnica no título.

07

Feedback rápido, ajuda graduada

Novatos recebem exemplos e pistas; a ajuda é retirada conforme a habilidade cresce.

08

Ownership acima de autoria

Mesmo com IA, você deve conseguir explicar, defender, modificar e depurar tudo que entrega.

02 · MOTOR DE APRENDIZAGEM

O loop que atravessa todas as fases

A dificuldade cresce; o ciclo permanece.

MODELConstrua o modelo mental e os invariantes.
TRACEPreveja estado, fluxo, memória, custo ou protocolo antes de executar.
BUILDImplemente sem copiar a solução.
BREAKCrie casos que façam soluções frágeis falharem.
EXPLAINExplique decisões e comportamento sem esconder-se atrás da sintaxe.
TRANSFERResolva uma variação sem tag e sem roteiro.
RETAINReteste depois de dias ou semanas.
SHIPQuando aplicável, entregue e opere em ambiente real.

Para iniciantes

Exemplo trabalhado → exercício semelhante → retirada gradual de pistas → problema independente.

Para intermediários

Problema → hipótese → implementação → teste → code review → variação sem tag → reteste.

Para avançados

Requisitos incompletos → trade-offs → sistema → falhas injetadas → incidentes → defesa arquitetural.

03 · FORMAÇÃO

O meu roadmap ideal

A ordem é por dependência cognitiva, não por moda de mercado.

00ORIENTAÇÃO

Computador como instrumento

primeiros dias

Antes de “aprender uma stack”, aprenda a observar o ambiente onde o programa vive.

Aprender

  • terminal, filesystem e processos
  • editor/IDE sem magia
  • Git e histórico
  • debugger, logs, profiler básico
  • entrada/saída e execução

Praticar

  • navegar e manipular arquivos no shell
  • usar breakpoints desde o início
  • ler stack trace antes de pesquisar
  • versionar todo exercício relevante

Gate

Consegue localizar onde o programa está, como executa, onde falhou e voltar a uma versão anterior sem tutorial.

MIT Missing Semester
01FLUÊNCIA

Programação fundamental

uma linguagem simples

Aprender a transformar estado e regras em programas pequenos, legíveis e testáveis.

Aprender

  • valores, tipos e expressões
  • condições e iteração
  • funções e decomposição
  • coleções e mutabilidade
  • erros, testes e invariantes

Praticar

  • finger exercises curtos
  • programas úteis pequenos
  • trace manual de execução
  • reescrever sem olhar

Gate

Recebe um problema pequeno, decompõe em funções, escreve testes e chega à solução sem tutorial passo a passo.

MIT 6.100L Aizu ITP1
02ABSTRAÇÃO

Abstração, paradigmas e complexidade

pensar acima da sintaxe

Aprender por que funções, objetos, interfaces, closures, iteradores e tipos existem — e quando não ajudam.

Aprender

  • abstração procedural e de dados
  • recursão e funções de alta ordem
  • OOP e composição
  • interfaces e contratos
  • noções de análise assintótica

Praticar

  • mesmo problema em dois paradigmas
  • construir mini-interpretador ou DSL
  • refatorar código procedural para abstrações
  • justificar cada camada criada

Gate

Consegue trocar a representação interna sem quebrar o contrato e explicar o custo e o benefício da abstração.

Berkeley CS61A 42 Method
03PROBLEM SOLVING

Estruturas de dados e algoritmos

ginásio deliberado

Não para “passar no LeetCode”, mas para aprender a reconhecer estrutura, custo e invariantes em problemas desconhecidos.

Aprender

  • arrays, listas, hash, stacks/queues
  • árvores, heaps e grafos
  • sorting e searching
  • greedy, backtracking e DP
  • complexidade de tempo e espaço

Praticar

  • séries curtas por padrão
  • problemas sem tag
  • contraexemplos e hacking
  • contests curtos
  • radar de competência por categoria

Gate

Consegue escolher uma estrutura, justificar Big-O, adaptar a solução quando a restrição muda e detectar solução aparentemente correta que falha.

04SISTEMAS

O que existe abaixo do código

C + máquina

O programador começa a enxergar memória, representação, compilação, CPU, processos e concorrência como parte do próprio código.

Aprender

  • C, ponteiros e layout de memória
  • assembly e calling conventions
  • cache e hierarquia de memória
  • processos, syscalls e virtual memory
  • threads, locks e I/O

Praticar

  • memory bugs deliberados
  • profiling e locality
  • ler assembly simples
  • modificar kernel didático
  • explicar custo de uma abstração de alto nível

Gate

Consegue seguir um valor do código fonte até memória/máquina e diagnosticar um bug de sistema sem tratar o runtime como caixa-preta.

Berkeley CS61C CMU 15-213 MIT 6.1810 / xv6
05DADOS

Persistência e bancos por dentro

dados com mecânica

SQL é só a superfície. O objetivo é compreender modelagem, storage, índices, execução, concorrência e recuperação.

Aprender

  • modelo relacional e normalização
  • índices e estruturas de storage
  • query planning/execution
  • ACID e isolation
  • logging, recovery e distribuição

Praticar

  • explicar plano de consulta
  • provocar lock/contention
  • implementar mini buffer/index
  • medir efeito de índice
  • debugging de query lenta

Gate

Consegue explicar por que uma consulta ficou lenta, escolher índice/transação e prever anomalias de concorrência.

CMU 15-445
06REDES

Software que conversa

protocolos, não endpoints

Antes de “API REST”, entender estado, bytes, latência, perda, retransmissão, timeout e protocolos.

Aprender

  • IP, TCP, UDP e DNS
  • HTTP e TLS
  • sockets e state machines
  • timeouts, buffering e backpressure
  • latência e largura de banda

Praticar

  • capturar tráfego
  • implementar protocolo pequeno
  • construir partes de TCP
  • simular perda e reordenação
  • diagnosticar timeout real

Gate

Consegue explicar uma requisição ponta a ponta e localizar se a falha está no aplicativo, protocolo, DNS, conexão ou servidor.

Stanford CS144
07ENGENHARIA

Construir software com outras pessoas

do código ao produto

A diferença entre “sei programar” e “sou engenheiro de software” aparece quando o código precisa sobreviver a mudança, equipe e tempo.

Aprender

  • testes, contratos e refactoring
  • modularidade, coesão e acoplamento
  • Git colaborativo e code review
  • requisitos e trade-offs
  • documentação e ADRs

Praticar

  • peer review obrigatório
  • reviewer mode em código alheio
  • projeto em equipe
  • mudança de requisito no meio
  • entrega documentada

Gate

Consegue revisar PR, defender design, mudar requisito sem reescrever tudo e deixar o sistema compreensível para outra pessoa.

Entregar, observar e recuperar

software vivo

Produção é um laboratório: ela ensina carga, falha, custo, operação, observabilidade e responsabilidade.

Aprender

  • CI/CD e release

  • logs, métricas e traces

construir pensando em abuso

Todo sistema possui entradas hostis, estados inesperados e suposições quebráveis. Segurança vira parte do design, não checklist final.

Aprender

  • validação e trust boundaries
  • vulnerabilidades web
  • segredos, crypto básica e supply chain

Praticar

  • quebrar a própria API
  • abuso de regras de negócio
  • security review
  • corrigir e retestar a mesma falha

05 · APRENDER NA ERA DA IA

IA não sai do currículo. Ela muda de papel.

O objetivo é aproveitar assistência sem terceirizar o esforço cognitivo que constrói habilidade.

MODO 1

Closed Loop

Primeira tentativa sem solução de IA. Pode usar documentação de referência quando a tarefa não estiver testando memória de API.

  • recall
  • trace
  • problema-base
  • gates de domínio
MODO 2

Tutor

A IA dá pista gradual, cria testes, questiona hipótese, compara alternativas e aponta categoria de erro — sem substituir a tentativa.

  • feedback
  • debugging guiado
  • review
  • retest
MODO 3

Production

Agentes e copilots são liberados para produtividade, mas o código entra em Code Ownership Gate.

  • explicar
  • defender
  • depurar
  • modificar sem assistência

CODE OWNERSHIP GATE

Se a IA escreveu, você ainda responde.

  1. Explique o fluxo e as invariantes.
  2. Aponte riscos, complexidade e trade-offs.
  3. Encontre um bug inserido sem aviso.
  4. Faça uma mudança de requisito.
  5. Defenda por que aceitaria esse código em produção.

07 · RITMO

Como uma semana de estudo deveria parecer

Proporção inicial; adaptar ao nível e ao objetivo.

25%

Modelo

Aula, leitura, exemplos trabalhados e perguntas profundas.

30%

Build

Exercícios, pequenos programas e implementação de mecanismos.

15%

Problem Gym

Problemas graduados e alguns sem tag.

15%

Debug / Break

Código quebrado, contraexemplos, profiling e incidentes.

10%

Review

Code review, explicação e comparação de soluções.

5%

Retest

Recuperação espaçada dos fundamentos que precisam permanecer.

Em fases de projeto e produção, Build/Ship cresce; em fundamentos, Model/Problem Gym cresce. Não existe proporção universal.

DEFINIÇÃO DE “APRENDEU”

Você não termina quando sabe a resposta.

Termina quando consegue chegar nela novamente, explicar por que funciona, encontrar onde quebra, adaptar quando o problema muda e assumir responsabilidade pelo comportamento do sistema.
